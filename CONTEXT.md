# BenihKode

BenihKode is a product studio site. Its main line is growing its own products from idea to shipped project to documented build; client services ride on top as the monetization layer, not the spine. The garden metaphor (benih = seed, kode = code) belongs to site copy; the terms below are the domain words.

## Language

### Identity

**Main Line**:
The graduation pipeline: Idea → Shipped Project → Build Story. Everything else on the site supports it.
_Avoid_: content strategy, throughline

**Services**:
The offer of building client products for hire. The monetization layer on top of the Main Line, never its replacement.
_Avoid_: freelance work, hire offering

### Content lifecycle

**Idea**:
A product concept written as a lightweight PRD, carrying a status lifecycle of `idea` → `in-progress` → `completed`.
_Avoid_: seed, concept, PRD (the document is the Idea's body, not the thing itself)

**Graduation**:
An Idea that ships and receives a Project card. A graduated Idea keeps its PRD; the PRD's status becomes `completed`.
_Avoid_: harvest, promotion

**Project**:
Umbrella term for shipped work, displayed in the Portfolio.
_Avoid_: product, repo

**App**:
A Project aimed at end users, often store-distributed with its own privacy policy page.
_Avoid_: consumer app, mobile app (Apps are not necessarily mobile)

**Tool**:
A Project aimed at developers: CLIs and dev utilities, without store distribution.
_Avoid_: devtool, utility

**Build Story**:
A Journal post documenting how a specific Project was built.
_Avoid_: devlog, case study

**Journal**:
The blog section as a whole. Contains Build Stories and standalone learning notes; only Build Stories are part of the Main Line.
_Avoid_: blog (in domain talk; fine in UI copy)

**Artifact Set**:
The four documents a flagship ship receives: Idea PRD, Project card, Build Story, privacy policy page (only when the App is store-distributed). One-off experiments may skip the PRD.
_Avoid_: full entry, complete set
